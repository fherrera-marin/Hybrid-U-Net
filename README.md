# Hybrid CNN + U-Net — CFD Field Prediction Around an Airfoil

A surrogate model based on a hybrid CNN + U-Net architecture that predicts the velocity fields
(`Ux`, `Uy`) and pressure field (`P`) around a 2D airfoil from its **Signed Distance Function
(SDF)**, avoiding the need to run a full CFD (OpenFOAM) simulation.

This repository contains **only the modeling part**: loading the pre-built dataset, model
definition, training, evaluation and visualization of results. Building the dataset
(`CNN_df.pkl`) from raw OpenFOAM results (meshing, interpolation to a uniform grid, SDF
computation, etc.) is done in a separate, external project and is **not part of this repo**.

## Execution order — full pipeline

All commands are run from the project root, with the virtual environment active. This is the
order to go from the dataset to predicting a specific SDF supplied by the user:

### 1. Make sure the dataset is in place

`data/CNN_df.pkl` (the full dataset) must exist locally — see [Input data](#input-data) below for
why it isn't tracked in this repository. Nothing else is required — no preprocessing step runs
here.

### 2. Train the model

```bash
python -m src.training.train
```

- Loads `data/CNN_df.pkl`, splits it into train / val / test (fractions and seed from
  `configs/config.yaml`), and fits min-max normalization **on the training set only**.
- Trains with early stopping on `val_loss`.
- Persists three artifacts needed by every later step:
  - `saved_models/*.weights.h5` — weights of the best model.
  - `saved_models/split_indices*.npz` — the exact `idx_train` / `idx_val` / `idx_test` used.
  - `saved_models/norm_params*.npz` — min/max used to normalize `SDF`, `Ux`, `Uy`, `P`.

### 3. Evaluate on the test hold-out set

```bash
python -m src.inference.evaluate
```

- Reloads the model weights and the split/normalization artifacts saved by `train.py` (so the
  test set is guaranteed to be the same one never seen during training).
- Predicts every case in `idx_test`, computes global and **near-wall** NMAE per field, and saves
  one SDF plot plus one Ux/Uy/P comparison plot per case to `data/results/`.
- Prints a summary table (MAE / NMAE per field) and a near-wall NMAE distribution plot for the
  whole test set.

### 4. Predict a specific SDF (user-supplied)

```bash
python -m src.inference.predict_sdf --sdf path/to/my_sdf.npy
```

- `--sdf` points to a `.npy` file with a single 2D SDF array, shape `(H, W)` matching
  `model.input_shape` in the config (256×512 by default), same convention as the rest of the
  project (physical distance to the wall, `<= 0` inside the airfoil).
- Loads the trained weights and normalization parameters persisted in step 2, runs inference, and
  saves to `data/results/`: the SDF plot, the predicted-field plot (`<name>_prediction.png`), and
  the raw predicted arrays (`<name>_fields.npz`, loadable with `np.load(...)["Ux"]`, `["Uy"]`,
  `["P"]`). Min/max/mean per field are printed to the console.
- There is no ground truth here — this is meant for a new SDF the user provides, not one already
  in the dataset.

For programmatic use (e.g. from a notebook), the same logic is available as a function — see
[`src/inference/predict.py`](src/inference/predict.py) and the loading code in
[`predict_sdf.py`](src/inference/predict_sdf.py):

```python
from src.models.unet_hybrid import unet_model_multi_output
from src.inference.predict import predict_fields

model = unet_model_multi_output(input_shape=(256, 512, 1))
model.load_weights("saved_models/best_model_256x512.weights.h5")

fields, sdf_vis = predict_fields(model, sdf_norm, norm_params)  # fields = {"Ux", "Uy", "P"}
```

`sdf_norm` must be normalized with the same `sdf_mn` / `sdf_mx` stored in
`saved_models/norm_params*.npz`, and `norm_params` is the `{"Ux": (min, max), "Uy": (min, max),
"P": (min, max)}` dict loaded from that same file.

## Input data

`data/CNN_df.pkl` is a `pandas.DataFrame` (one row per simulation) with the columns:

| Column              | Shape       | Description                                                          |
|----------------------|-------------|------------------------------------------------------------------------|
| `SDF`                | (256, 512)  | Signed Distance Function on the uniform grid. `< 0` inside the airfoil. |
| `Ux_discretized`      | (256, 512)  | Interpolated x-velocity component (m/s).                              |
| `Uy_discretized`       | (256, 512)  | Interpolated y-velocity component (m/s).                               |
| `P_discretized`         | (256, 512)  | Interpolated pressure (Pa).                                             |

Grid: 256×512 (height × width), divisible by 8 (required by the 3 `MaxPooling2D` layers of the
encoder). Cells inside the airfoil (`SDF < 0`) are clamped to 0 in `SDF`, `Ux`, `Uy` and `P`
before training.

**Note on the dataset file**: the full `data/CNN_df.pkl` (200 simulations, ~840 MB) is **not**
tracked in this repository — it must be provided locally, at that same path, before running
`train.py` or `evaluate.py`. Instead, [`data/CNN_df_sample.pkl`](data/CNN_df_sample.pkl) ships in
the repo: the same 4 columns and format, reduced to the first 20 rows (~84 MB), meant as a
lightweight reference for the expected structure — not for real training or evaluation.

## Model architecture

[`unet_model_multi_output()`](src/models/unet_hybrid.py) — a single shared CNN encoder feeding
**three independent U-Net decoders**, one per output field:

1. **Shared encoder**: 3 blocks of `Conv2D → Conv2D → MaxPooling2D` (16 → 32 → 64 filters),
   followed by a bottleneck (`Conv2D`, 128 filters).
2. **CNN → U-Net transition**: `GlobalAveragePooling2D` on the bottleneck (instead of `Flatten`,
   to avoid OOM on large grids) + `Dense` + `Reshape` to `(H/8, W/8, 32)`.
3. **Three U-Net decoders** (Ux, Uy, P), each with 3 `Conv2DTranspose` blocks + skip connections
   to the encoder activations (`c1`, `c2`, `c3`) + a final linear `1×1` `Conv2D`.

Input: `(256, 512, 1)` — normalized SDF. Outputs: three `(256, 512, 1)` maps (Ux, Uy, P).

## Loss function

[`src/training/losses.py`](src/training/losses.py) implements an **MSE weighted by proximity to
the wall**:

- `compute_sdf_weights(sdf_batch, alpha)`: from the normalized SDF, computes a weight map
  `exp(-alpha * sdf)`, masking out the airfoil interior (`sdf == 0`) and normalizing by the
  batch mean. Higher `alpha` concentrates more weight near the wall.
- `weighted_mse(y_true, y_pred, weights)`: pixel-wise MSE multiplied by that weight map.

The total loss at each training step is the sum of `weighted_mse` over Ux + Uy + P, using the
same weight map (derived from the input SDF) for all three fields.

## Configuration (`configs/config.yaml`)

| Section       | Key                        | Description                                                              |
|----------------|-----------------------------|------------------------------------------------------------------------------|
| `model`        | `input_shape`                | Model input shape `[H, W, channels]`.                                        |
| `training`      | `epochs`                      | Maximum number of epochs.                                                    |
|                | `batch_size`                    | Batch size.                                                                   |
|                | `learning_rate`                   | Adam optimizer learning rate.                                                 |
|                | `val_size` / `test_size`            | Validation and test hold-out fractions over the full dataset.                 |
|                | `random_state`                        | Split seed (reproducibility).                                                 |
|                | `patience`                              | Epochs without improvement before early stopping.                             |
|                | `loss_alpha`                              | `alpha` of the near-wall weighting in the loss.                               |
| `evaluation`    | `nearwall_cells`                        | Near-wall threshold = `nearwall_cells × Δ` (Δ = min. non-zero SDF per case).  |
| `paths`         | `dataset`                                | Path to `CNN_df.pkl`.                                                          |
|                | `saved_model`                              | Path to the trained model weights.                                            |
|                | `split_indices`                              | Path to the persisted train/val/test indices.                                 |
|                | `norm_params`                                  | Path to the persisted normalization (min/max) parameters.                     |
|                | `results_dir`                                    | Folder where `evaluate.py` / `predict_sdf.py` save plots.                     |

## Generated outputs

- `saved_models/*.weights.h5` — best model weights (by `val_loss`).
- `saved_models/split_indices*.npz` — `idx_train`, `idx_val`, `idx_test` indices.
- `saved_models/norm_params*.npz` — min/max of `SDF`, `Ux`, `Uy`, `P` (fit on train only, no
  leakage).
- `data/results/sim_XXX_SDF.png` / `<name>_SDF.png` — SDF plot for each evaluated/predicted case.
- `data/results/sim_XXX_{Ux,Uy,P}.png` — prediction vs. OpenFOAM comparison + NMAE error map
  (`evaluate.py`, test set only — the only place ground truth is available).
- `data/results/nearwall_error_distribution.png/.pdf` — near-wall NMAE distribution across the
  test set (generated by `evaluate.py` only).
- `data/results/<name>_prediction.png` and `<name>_fields.npz` — predicted Ux/Uy/P plot and raw
  arrays for a user-supplied SDF (`predict_sdf.py` only).

## Notes

- The split and normalization are fit **only on the training set**, to avoid data leakage into
  validation/test.
- Metrics are reported as **NMAE** (`MAE / (y_max - y_min) × 100`), both globally (whole fluid
  domain, excluding the airfoil interior) and **near-wall** (cells within `nearwall_cells × Δ` of
  the wall).
- `saved_models/*.h5` (weights) is not versioned (see `.gitignore`) — it must be regenerated by
  running `train.py`. The `.npz` index/normalization files currently *are* versioned, but they
  come from a run prior to the migration to the 256×512 resolution: their names
  (`norm_params.npz` / `split_indices.npz`) don't match what `configs/config.yaml` currently
  expects (`norm_params_256x512.npz` / `split_indices_256x512.npz`). Re-run `train.py` to
  regenerate them under the correct names before evaluating or predicting.
